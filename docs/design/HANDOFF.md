# โต๊ะว่าง — Design Handoff

ระบบจองโต๊ะร้านอาหาร + community รีวิวร้าน (DevPool Final Exam 2569)

- **Canvas (source of truth ของหน้าตา):** https://claude.ai/artifact/GhwP3FfMxLiqvCzk9yJfE1 — มี 2 หน้า: `Desktop` (1440px) และ `มือถือ` (390px) ทุก artboard กด Play แล้วลองใช้ได้
- **Tech stack:** ยังไม่ล็อกในเอกสารนี้ — ไปตัดสินใจใน session dev (โจทย์บังคับ: หน้าเว็บ Next.js, backend API Go, กติกาการจองต้องตรวจที่ Go เสมอ)
- เอกสารนี้อธิบาย **หน้าตา + พฤติกรรมที่เห็นใน UI** เท่านั้น ไม่ได้กำหนดโครงสร้างโค้ด

> สถานะของแต่ละข้อ: **[โจทย์]** = มาจาก brief ของการสอบ · **[ดีไซน์]** = ตัดสินใจตอนออกแบบ ปรับได้ · **[ต้องคุย]** = ยังไม่มีข้อสรุป

## 1. โครงสร้างไฟล์ในแพ็กนี้

```
design-handoff/
├── HANDOFF.md                 ← ไฟล์นี้
├── tokens/
│   ├── tokens.css             ← CSS variables + utility class ของลายไทย
│   └── tokens.json            ← ค่าเดียวกันแบบ JSON (เอาไปแปลงเป็น Tailwind/theme ได้)
├── assets/                    ← SVG ที่วาดเอง ใช้ได้ไม่ติดลิขสิทธิ์
│   ├── logo-seal.svg                    โลโก้ตราชาด / favicon
│   ├── prajamyam.svg                    ลายประจำยาม (icon, ใช้ currentColor)
│   ├── pattern-prajamyam-tile.svg       พื้นลาย tile 84×126 (ทองบนคราม)
│   ├── pattern-prajamyam-tile-light.svg พื้นลาย tile (ชมพูอ่อน บนชาด — หัวใบจอง)
│   ├── band-kruay-choeng-indigo.svg     แถบกรวยเชิง tile 18×16 (ใต้ header)
│   └── band-kruay-choeng-red.svg        แถบกรวยเชิง tile 18×16 (ใต้ hero / ใบจอง)
└── reference/                 ← source ของ artboard (.dc.html) เปิดอ่าน style/logic ได้
    ├── desktop/*.dc.html
    └── mobile/M*.dc.html
```

**เกี่ยวกับ `reference/*.dc.html`:** เป็นไฟล์ของเครื่องมือออกแบบ **ไม่ใช่ production code** และเปิดตรง ๆ ในเบราว์เซอร์ไม่ได้ (ต้องใช้ runtime ของ canvas) ใช้เป็นสเปกได้ 2 แบบ:
- inline `style="…"` = ค่า spacing / ขนาด / สีที่ถูกต้อง
- `<script type="text/x-dc">` → `renderVals()` = logic ตัวอย่างของ UI (ตรวจที่นั่ง, เรียงร้าน, ตรวจฟอร์ม) — เป็นแค่ mock ฝั่ง UI, **ของจริงต้องตรวจที่ backend**
- ลายไทยในไฟล์ reference วาดเป็น path ยาวทั้งผืน — production ให้ใช้ tile ใน `assets/` แทน

### ตัวอักษร (Google Fonts, ใช้ฟรี — OFL)
| บทบาท | ฟอนต์ | ขนาด (desktop / mobile) |
|---|---|---|
| Display (h1 หน้า) | Pridi 600, letter-spacing −0.01em | 52–56 / 32 |
| หัวข้อส่วน (h2) | Pridi 600 | 26–30 / 22–24 |
| หัวการ์ด / ชื่อร้าน | Pridi 600 | 22 / 18 |
| ตัวเลขเด่น (คะแนน, วันที่ต้นขั้ว, stepper) | Pridi 600 | 22–60 |
| Body | Sarabun 400/500 | 16–18 / 15–16 |
| Label / ปุ่ม | Sarabun 600–700 | 15–17 |
| Caption | Sarabun 400 | 13–14 (ขั้นต่ำ 12) |

ตัวเลขข้อมูล (เวลา, จำนวนคน, คะแนน) ใช้**เลขอารบิก** · เลขไทย (๑ ๒ ๓ ๔) ใช้**เฉพาะลำดับขั้นตอน**ที่เป็นการตกแต่ง **[ดีไซน์]**

### รูปทรง
- radius: ปุ่ม/input `8px` · การ์ด `12–14px` · ใบจอง `16px` · chip/segmented `999px`
- **ทรงซุ้ม (dome)** สำหรับรูปร้านทุกที่: `border-radius: 50% 50% 10px 10px / 34% 34% 10px 10px` (สัดส่วนแนวตั้ง 22–34% ตามความสูงรูป)
- เงาการ์ด: `0 2px 0 var(--color-line)` (เงาแบบกระดาษ ไม่ฟุ้ง)

### Layout
- Desktop: artboard 1440, เนื้อหากว้าง 1200 (padding ข้าง 120) · หน้าร้าน: คอลัมน์ซ้ายยืด + ใบจอง 470px ขวา · การจองของฉัน: เนื้อหา 960 (padding 240)
- Mobile: 390, padding ข้าง 16, tab bar สูง ~84 (รวม safe area 24)
- Breakpoint แนะนำ **[ต้องคุย]**: < 768 ใช้ layout มือถือ, ≥ 1024 ใช้ layout desktop, ช่วงกลางให้ grid ร้านเหลือ 2 คอลัมน์

## 6. พฤติกรรม / กติกาที่ UI ต้องสื่อ

> ทุกข้อ **ต้องบังคับที่ backend ด้วย** — UI ตรวจซ้ำได้เพื่อ UX แต่ห้ามตรวจแค่หน้าเว็บ **[โจทย์]**

**บัญชี**
- สมัครครั้งเดียว ใช้ได้ทั้ง Owner และลูกค้า — ร้านที่ตัวเองสร้าง = owner, ร้านคนอื่น = ลูกค้า/ผู้รีวิว **[โจทย์]**
- แก้ไข/ลบได้เฉพาะร้านของตัวเอง — ต้องกันที่ API ไม่ใช่แค่ซ่อนปุ่ม **[โจทย์]**
- ฟอร์มสมัคร: รหัสผ่าน ≥ 8 ตัว + มีตัวเลข + ยืนยันตรงกัน + ติ๊กยอมรับ **[ดีไซน์ — ปรับได้]**

**ร้าน**
- ฟิลด์: ชื่อ, รายละเอียด, รูป ≥ 1, จำนวนที่นั่ง (นับรวม ไม่แยกโต๊ะ), เวลาเปิด–ปิด, เวลายกเลิกล่วงหน้า **[โจทย์]**
- เวลายกเลิกล่วงหน้า: default 30 นาที, เพิ่มได้, **ห้ามต่ำกว่า 30** · UI: stepper ทีละ 15 นาที + ปุ่มลัด 30น./1ชม./2ชม./3ชม. **[โจทย์ + ดีไซน์]**
- เวลาปิด < เวลาเปิด = **ปิดข้ามเที่ยงคืน** (เช่น 18:00–02:00) → แสดง badge + คำอธิบาย, ช่วงหลัง 00:00 นับเป็นรอบของคืนเดียวกัน **[โจทย์ถามไว้ / ดีไซน์ตอบแบบนี้]**

**การจอง** — ลูกค้ากรอก 3 อย่าง: จำนวนคน, วันที่, เวลาเริ่ม–สิ้นสุด **[โจทย์]**
- จองสำเร็จเมื่อ: อยู่ในเวลาเปิดร้าน · ไม่ใช่เวลาที่ผ่านไปแล้ว · ที่นั่งไม่เกิน **[โจทย์]**
- ที่นั่ง: **ทุกช่วงเวลา** ผลรวมคนที่จองซ้อนกันต้อง ≤ จำนวนที่นั่ง — UI แบ่งเป็นช่อง 30 นาที และบอกช่วงแรกที่เกิน เช่น "ช่วง 12:00–12:30 จองแล้ว 7 + คุณ 4 = 11 เกิน 10 ที่" **[โจทย์ + ดีไซน์]**
- ตัวเลือกเวลาในดีไซน์ทีละ 30 นาที **[ดีไซน์ — ต้องคุยว่าจะบังคับหรือไม่]**
- แก้ไขการจอง = ตรวจกติกาเดียวกับจองใหม่ **แต่ไม่นับที่นั่งเดิมของการจองนี้ซ้ำ** (A 7→8 เมื่อ B จอง 3: ต้องใช้ 11 ✕ / A 7→5 ✓) **[โจทย์]**
- ยกเลิกได้ถึง `เวลาเริ่ม − เวลายกเลิกล่วงหน้าของร้าน` — เลยแล้วปุ่มยกเลิก disabled + บอกเวลาที่เลยไป **[โจทย์]**
- หลังเลยเวลายกเลิก ดีไซน์ยัง**ให้แก้ไขได้** **[ต้องคุย]**
- สองคนกดจองที่นั่งสุดท้ายพร้อมกัน → ต้องกันที่ backend (transaction/lock) — UI แค่แสดง error ที่ backend ส่งกลับ **[โจทย์ถามไว้ — ต้องคุย]**

**รีวิว**
- ดาวจำนวนเต็ม 1–5 + ข้อความ · รีวิวร้านตัวเองไม่ได้ **[โจทย์]**
- แสดงค่าเฉลี่ยทศนิยม 1 ตำแหน่ง + จำนวนรีวิว **[โจทย์]**
- เรียง "คะแนนสูงสุด": ร้านที่มีรีวิว **< 5** ไปอยู่ท้ายรายการ + badge "รีวิวยังน้อย" (ตอบคำถาม 5.0 จาก 1 รีวิว vs 4.8 จาก 300) **[ดีไซน์ — เกณฑ์ 5 ปรับได้ / อาจเปลี่ยนเป็น Bayesian average]**
- เรียง "รีวิวมากสุด": จำนวนรีวิวมาก → น้อย **[โจทย์]**
- ค่าเฉลี่ยคำนวณสดหรือเก็บ cache **[โจทย์ถามไว้ — ต้องคุย]**
- ดีไซน์ไม่ได้กำหนดว่ารีวิวได้กี่ครั้งต่อร้าน / ต้องเคยจองก่อนไหม **[ต้องคุย]**

## 8. Accessibility ที่ออกแบบไว้แล้ว

- ปุ่ม/ลิงก์จริง (`<button>`, `<a>`, `<input>` + `<label>`), ปุ่มไอคอนมี `aria-label`
- touch target ≥ 44px ทุกปุ่ม
- ตัวอักษรผ่าน contrast 4.5:1 (ทองใช้เฉพาะตกแต่ง, ตัวอักษรทองใช้ `#7A5A12`)
- สถานะไม่ได้สื่อด้วยสีอย่างเดียว — มีไอคอน ✓/✕ + ข้อความเสมอ
- ผลตรวจที่นั่ง/จำนวนคนใช้ `aria-live` / `role="status"`; segmented ใช้ `aria-pressed`; สวิตช์ใช้ `role="switch"`
