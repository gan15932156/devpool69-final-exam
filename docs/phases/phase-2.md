# Phase 2 — ร้าน

**ผลลัพธ์:** หน้าค้นหาร้าน · หน้าร้าน · ฟอร์มสร้าง/แก้ไข/ลบร้านพร้อมอัปโหลดรูป · คนอื่นแก้/ลบร้านเราไม่ได้ (403 ที่ API)

## API

| Method | Path | สิทธิ์ | หมายเหตุ |
|---|---|---|---|
| GET | `/restaurants?q=&sort=` | ใครก็ได้ | ค่าเฉลี่ย + จำนวนรีวิวคำนวณสด |
| GET | `/restaurants/:id` | ใครก็ได้ | + การกระจายดาว 1–5 |
| POST | `/restaurants` | login | เจ้าของ = คนที่ login |
| PUT | `/restaurants/:id` | เจ้าของ | |
| DELETE | `/restaurants/:id` | เจ้าของ | ยังมีการจองที่ยังไม่จบ → 409 |
| GET | `/me/restaurants` | login | |
| POST | `/uploads` | login | multipart → `{ url }` |

## การตัดสินใจ และเหตุผล

| เรื่อง | เลือก | ทำไม | ทางอื่นที่ไม่เลือก |
|---|---|---|---|
| เช็กเจ้าของ | `ownedRestaurant()` ที่ API **ทุกครั้ง** | โจทย์: ต้องกันที่ API ไม่ใช่แค่ซ่อนปุ่ม · คนยิง API ตรงได้เสมอ | ซ่อนปุ่มในหน้าเว็บอย่างเดียว |
| คะแนนเฉลี่ย | `LEFT JOIN reviews` + `ROUND(AVG,1)` + `COUNT` สด | ข้อมูลตรงเสมอ ไม่ต้อง sync · ข้อมูลระดับนี้ query เร็วพอ · ย้ายมาทำใน Phase 2 (ไม่รอ Phase 5) เพราะการ์ดร้านต้องแสดงตราคะแนน | เก็บ cache ในตารางร้าน: เร็วกว่าตอนข้อมูลเยอะ แต่ต้องอัปเดตทุกครั้งที่มีรีวิว เสี่ยงค่าไม่ตรง |
| ร้านไม่มีรีวิว | `avgRating: null` | ต่างจาก "ได้ 0 ดาว" · หน้าเว็บแสดง "–" | ส่ง 0: สับสนกับคะแนนจริง |
| `hasEnoughReviews` | คิดที่ Go จาก `MinReviewsForRanking = 5` | เกณฑ์อยู่ที่เดียว หน้าเว็บไม่ต้องรู้เลข 5 | ให้หน้าเว็บเช็ก `reviewCount < 5` เอง: เลขซ้ำสองที่ |
| ค้นหา | `ILIKE` ชื่อ + ประเภทอาหาร | ไม่สนตัวพิมพ์เล็กใหญ่ · พอสำหรับร้านไม่กี่ร้อย | full-text search: เกินความจำเป็น |
| อัปโหลด: ตรวจชนิดไฟล์ | `http.DetectContentType` จาก **512 byte แรกของเนื้อไฟล์** | นามสกุลและ Content-Type ผู้ใช้ปลอมได้ · ทดสอบแล้ว: ไฟล์ข้อความเปลี่ยนชื่อเป็น .jpg ถูกปฏิเสธ | เชื่อนามสกุลไฟล์ |
| อัปโหลด: ชื่อไฟล์ | สุ่ม 32 ตัวอักษร hex (crypto/rand) | กันชื่ออย่าง `../../main.go` (path traversal) และชื่อชนกัน | ใช้ชื่อที่ผู้ใช้ส่งมา |
| อัปโหลด: เก็บที่ไหน | โฟลเดอร์ `api/uploads` + Docker volume | ง่าย พอสำหรับงานนี้ · ไม่ต้องสมัคร cloud | S3/Cloudinary: ต้องมีบัญชีและ key |
| รูปในฟอร์มร้าน | รับเฉพาะ URL ที่ขึ้นต้น `/uploads/` | กันใส่ลิงก์รูปจากเว็บอื่น | — |
| แก้ไขร้าน: รูป | ลบของเดิมทั้งหมดแล้วใส่ใหม่ใน transaction | ลำดับรูป (รูปหลัก) ถูกต้องเสมอ โค้ดสั้น | diff ทีละรูป: ซับซ้อนเกินจำเป็น |
| อัปเดตด้วย `map` | `Updates(map[string]any{...})` | GORM ข้ามค่าศูนย์ถ้าส่ง struct (เช่น description ว่าง จะไม่ถูกอัปเดต) | ส่ง struct |
| ลบร้าน | ห้ามถ้ามีการจอง `confirmed` ที่ `end_at > now` → 409 | ลูกค้าที่จองไว้จะไม่หายไปเฉย ๆ · ที่เหลือ (รูป, การจองเก่า, รีวิว) ลบตามด้วย `ON DELETE CASCADE` | ลบได้เสมอ: ลูกค้าเสียการจอง |
| เปลี่ยนที่นั่ง/เวลาร้าน | การจองเดิมยังอยู่ | กติกาใหม่ใช้กับการจองใหม่/การแก้ไขครั้งถัดไป (ตามที่ตกลงใน WALKTHROUGH) | ยกเลิกการจองที่ขัดกติกาใหม่อัตโนมัติ |
| เวลาเปิด/ปิดในฟอร์ม | `<select>` ทีละ 30 นาที | เลือกได้แค่ค่าที่ถูกต้อง (:00/:30) · `<input type="time">` พิมพ์นาทีอะไรก็ได้และหน้าตาต่างกันทุกเบราว์เซอร์ | input type=time |
| ปิด ≤ เปิด | = ปิดข้ามเที่ยงคืน + แสดงคำอธิบาย | ตามดีไซน์ · 18:00–02:00 ต้องใช้ได้ | บังคับให้ปิด > เปิด: ร้านโต้รุ่งใช้ไม่ได้ |
| ประเภทร้าน (cuisine) | เพิ่มช่องในฟอร์ม ไม่บังคับ | การ์ดในดีไซน์แสดง แต่ฟอร์มในดีไซน์ไม่มี | — |
| ตัวอย่างการ์ดในฟอร์ม | ใช้ `RestaurantCard` ตัวจริง | ดีไซน์มีช่อง "ตัวอย่างในหน้าค้นหา" · ใช้ component เดียวกันจึงตรงกันเสมอ | — |
| ค้นหา | หน่วง 300ms + เก็บ `q`, `sort` ใน URL | ไม่ยิง API ทุกตัวอักษร · reload/แชร์ลิงก์แล้วได้ผลเดิม | — |
| รูป | `next/image` แบบ `unoptimized` | รูปมาจาก Go ผ่าน rewrite ไม่ต้องให้ Next ย่อซ้ำ · ไม่โดน lint `no-img-element` | `<img>`: lint เตือน |
| หน้าร้าน | server page อ่าน `params` → client component ดึงข้อมูล | Next 16: `params` เป็น Promise ต้อง `await` · ข้อมูลใช้ cache เดียวกับฟอร์ม/ใบจอง (TanStack Query) | — |
| className ซ้อนกัน | เพิ่ม variant ใหม่ (`outline-red`) แทนการส่ง class ทับ | ไม่มี tailwind-merge → class ที่ชนกัน ลำดับใน CSS เป็นตัวตัดสิน ไม่ใช่ลำดับที่เขียน | ติดตั้ง tailwind-merge |

## ทดสอบแล้ว

- ฟอร์มผิดทุกช่อง → 400 พร้อม `details` 6 ช่อง · เปิด = ปิด → 400 · รูปจากเว็บอื่น → 400

- ลบร้านที่มีการจองพรุ่งนี้ → 409 `HAS_FUTURE_BOOKINGS` · มีแค่การจองเก่า → 204 และรูป/การจองเก่าหายตาม
