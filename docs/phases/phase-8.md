## สิ่งที่ต้องอธิบายในส่วนโค้ด (ฝึกพูดให้ได้โดยไม่ดูโน้ต)

1. **ทำไมล็อกแถวร้าน** — ทุกการจอง/แก้/ยกเลิกของร้านเดียวกันต้องผ่าน `SELECT … FOR UPDATE` ที่แถวร้านก่อน คนที่สองต้องรอคนแรก commit แล้วจึงเห็นการจองของคนแรก · ทดลองเอา lock ออกแล้ว 3 ใน 5 รอบจองเกิน (ดู phase-3.md)
2. **ทำไมใช้ `tx` ทุกคำสั่ง** — query ที่ใช้ `db` ข้างนอกจะไม่อยู่ใน transaction → lock ไม่คุม
3. **ตรวจกติกาตามลำดับ** — ลง :00/:30 → จบหลังเริ่ม → อยู่ในเวลาเปิด → ยังไม่ผ่านไป · แต่ละข้อมี error code ของตัวเอง
4. **ร้านข้ามเที่ยงคืน** — `Resolve()` ใน `time.go`: เวลาในช่วง 00:00 ถึงเวลาปิด ของร้านที่ปิด ≤ เปิด เป็นของวันถัดไป · เก็บ `service_date` เป็นวันของรอบ เจ้าของร้านจึงเห็นในคืนเดียวกัน
5. **ทำไมวนทีละ 30 นาที** — ต้องรู้ว่า ณ เวลาหนึ่งมีคนนั่งพร้อมกันกี่คน · เวลาจองลง :00/:30 เสมอ จำนวนคนจึงเปลี่ยนได้แค่ที่ขอบช่อง · การจอง 12:00–12:30 กับ 12:30–13:00 ไม่ได้ซ้อนกันเอง ถ้าเอามารวมทั้งช่วงจะนับเกินจริง
6. **แก้ไขไม่นับซ้ำ** — `CheckSeats(..., excludeID)` → query ใส่ `id <> ?`

## คำถามที่กรรมการอาจถาม (คำตอบสั้น)

| คำถาม | ตอบ |
|---|---|
| สองคนจองที่นั่งสุดท้ายพร้อมกัน? | transaction + FOR UPDATE ที่แถวร้าน → เข้าคิว คนที่สองเห็นที่นั่งเต็ม → 409 · เดโมด้วย race.sh |
| ทำไมไม่ SERIALIZABLE / unique constraint? | SERIALIZABLE ต้องเขียน retry · unique ใช้ไม่ได้เพราะนับที่นั่งรวม ไม่มีแถวให้ unique |
| 5.0 จาก 1 รีวิว vs 4.8 จาก 300? | รีวิวไม่ถึง 5 ไปท้าย + ป้ายบอก · ทางที่ดีกว่าทางสถิติคือ Bayesian average แต่ผู้ใช้เข้าใจยากกว่า |
| ค่าเฉลี่ยคำนวณสดหรือ cache? | สด (`AVG`, `COUNT` + LEFT JOIN) — ตรงเสมอ ข้อมูลระดับนี้เร็วพอ · ถ้าข้อมูลใหญ่ค่อยเก็บ cache แล้วอัปเดตใน transaction เดียวกับรีวิว |
| client อ่าน token ได้ไม่เสี่ยงเหรอ? | เสี่ยงถ้ามี XSS · React escape ให้ ไม่ใช้ `dangerouslySetInnerHTML` token อายุ 7 วัน · แน่นกว่านี้ต้องทำ BFF ไม่ส่ง token ลง browser |
| ทำไมต้องตรวจที่ Go ถ้าหน้าเว็บตรวจแล้ว? | คนยิง API ตรงได้ (เดโมด้วย requests.http) · หน้าเว็บตรวจเพื่อ UX เท่านั้น |
| เปลี่ยนที่นั่งร้านตอนมีการจองอยู่? | การจองเดิมอยู่ต่อ กติกาใหม่ใช้กับการจอง/แก้ไขครั้งถัดไป |
| ลบร้านที่มีการจอง? | ห้าม → 409 จนกว่าการจองที่ยังไม่จบจะหมด |
| ทำไมเก็บเวลาเปิด/ปิดเป็นนาทีนับจากเที่ยงคืน? | ไม่มีวันที่ · 18:00 = 1080 → กติกาเป็นการเทียบเลข (ปิด ≤ เปิด = ข้ามคืน · หาร 30 ลงตัว = ลงครึ่งชั่วโมง) ไม่ต้องยุ่งกับ timezone |
| ค่าเฉลี่ยคิดยังไง? | รวมดาวทุกรีวิว ÷ จำนวนรีวิว เช่น 285 ÷ 80 = 3.56 → ปัดเป็น 3.6 (`ROUND(AVG(rating), 1)`) |
| ทำไมนับรีวิวด้วย `COUNT(reviews.id)`? | LEFT JOIN ทำให้ร้านที่ไม่มีรีวิวมีแถว NULL 1 แถว · `COUNT(*)` ได้ 1 · `COUNT(reviews.id)` ได้ 0 |
| ต้องเคยจองก่อนถึงรีวิวได้ไหม? | ไม่ต้อง · แค่ login และไม่ใช่เจ้าของร้าน (เจ้าของยิง API ตรงได้ 403 `OWN_RESTAURANT`) |
