# Phase 6 — Dashboard เจ้าของร้าน

**ผลลัพธ์:** หน้า `/owner` · สลับร้าน · แบนเนอร์ร้าน · ตัวเลขสรุป 4 ช่อง · เลือกวัน · กราฟที่นั่งรายช่อง 30 นาที · ตารางการจองของวันนั้น

## API

| Method | Path | หมายเหตุ |
|---|---|---|
| GET | `/restaurants/:id/bookings?date=` | เจ้าของเท่านั้น · ชื่อลูกค้า / จำนวนคน / เวลา / สถานะ |
| GET | `/me/restaurants` | (จาก Phase 2) รายการร้านของฉัน |
| GET | `/restaurants/:id/availability?date=` | (จาก Phase 3) ใช้วาดกราฟ |

## ไฟล์หลัก

`api/internal/handlers/owner.go` · `web/app/(main)/owner/OwnerDashboard.tsx` · `web/components/booking/SeatTimeline.tsx` (เพิ่ม `height`)

## การตัดสินใจ และเหตุผล

| เรื่อง | เลือก | ทำไม | ทางอื่นที่ไม่เลือก |
|---|---|---|---|
| สิทธิ์ดูรายการจอง | `ownedRestaurant()` (ใน `handlers/handler.go`) ตัวเดียวกับแก้/ลบร้าน | ชื่อลูกค้าเป็นข้อมูลส่วนตัว ให้เห็นเฉพาะเจ้าของร้าน | — |
| กรองตามวัน | `service_date = ?` | ร้านโต้รุ่ง: การจอง 00:00–01:00 ของคืนวันที่ 26 ต้องอยู่ในรายการ "26" ไม่ใช่ "27" · นี่คือเหตุผลที่มีคอลัมน์ `service_date` | กรองด้วย `start_at` ช่วงวัน: การจองหลังเที่ยงคืนไปโผล่อีกวัน |
| แสดงการจองที่ยกเลิก | แสดง (สีจาง + ป้าย "ยกเลิกแล้ว") | เจ้าของรู้ว่ามีคนยกเลิก | ซ่อน |
| กราฟ | **ใช้ availability endpoint ตัวเดิม** + component `SeatTimeline` ตัวเดิม (ขยายสูง 160px) | ตัวเลขเจ้าของเห็น = ลูกค้าเห็น = ที่ Go ใช้ตัดสิน · ไม่มีโค้ดซ้ำ | เขียน query/กราฟใหม่ |
| ร้านที่เลือก | เก็บใน URL `?r=id` | reload แล้วอยู่ร้านเดิม · ลิงก์ "จัดการร้าน" จากหน้าค้นหาเปิดร้านนั้นตรง ๆ | state อย่างเดียว |
| ตัวสลับร้านบนมือถือ | แถวเลื่อนแนวนอน · desktop เป็นคอลัมน์ 320px | ตามดีไซน์ desktop · มือถือไม่มีที่ให้คอลัมน์ | — |
| ยังไม่มีร้าน | empty state + ปุ่มสร้างร้าน | ผู้ใช้ใหม่ทุกคนเจอหน้านี้ก่อน | — |
| ปุ่มลบในแบนเนอร์ | ไม่ใส่ (ลบได้ในหน้าแก้ไขร้าน) | การลบต้องมีขั้นยืนยันและแสดง error 409 — อยู่ในฟอร์มที่เดียวพอ | ใส่สองที่: โค้ดยืนยันซ้ำ |
