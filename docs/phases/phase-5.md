# Phase 5 — รีวิว + การเรียง

**ผลลัพธ์:** ส่วนรีวิวในหน้าร้าน (สรุปคะแนน · การกระจายดาว · star picker · รายการรีวิว) · เจ้าของเห็นกล่องล็อก · หน้าค้นหาเรียงตามคะแนน/จำนวนรีวิว · การจองที่ผ่านมามีปุ่ม "เขียนรีวิว" / ป้าย "รีวิวแล้ว"

## API

| Method | Path | หมายเหตุ |
|---|---|---|
| GET | `/restaurants/:id/reviews?offset=` | ล่าสุดก่อน ทีละ 20 · login อยู่ได้ `mine` (เฉพาะหน้าแรก `offset=0`) |
| PUT | `/restaurants/:id/reviews/me` | upsert · เจ้าของ → 403 `OWN_RESTAURANT` |
| GET | `/restaurants?sort=rating\|reviews` | เพิ่มการเรียง |

## ไฟล์หลัก

`api/internal/handlers/reviews.go` · `restaurants.go` (sort) · `web/components/review/ReviewsSection.tsx`

## การตัดสินใจ และเหตุผล

| เรื่อง | เลือก | ทำไม | ทางอื่นที่ไม่เลือก |
|---|---|---|---|
| รีวิวกี่ครั้ง | **1 คน / 1 ร้าน** แก้ได้ | ตกลงไว้ · กันคนเดียวปั่นคะแนน | รีวิวได้หลายครั้ง: คะแนนเบี้ยว |
| ต้องเคยจองก่อนไหม | ไม่ต้อง | ตกลงไว้ · โจทย์ไม่ได้บังคับ | ต้องมีการจองที่ผ่านมาแล้ว: เข้มกว่า แต่ seed/เดโมยากขึ้น |
| กันรีวิวซ้ำ | unique index `(restaurant_id, user_id)` + `INSERT … ON CONFLICT DO UPDATE` | DB เป็นตัวกันจริง แม้กดพร้อมกันสองแท็บ · คำสั่งเดียวได้ทั้งสร้างและแก้ | SELECT ก่อนแล้วค่อย INSERT/UPDATE: มีช่องให้ซ้ำ |
| ใช้ `PUT /reviews/me` | ไม่ใช่ `POST /reviews` | "รีวิวของฉันที่ร้านนี้" มีได้อันเดียว → PUT (แทนที่) ตรงความหมาย | POST + PUT แยก: หน้าเว็บต้องรู้ก่อนว่าเคยรีวิวไหม |
| รีวิวร้านตัวเอง | 403 ที่ API + กล่องล็อกในหน้าเว็บ | โจทย์บังคับ · ต้องกันที่ API | ซ่อนฟอร์มอย่างเดียว |
| คะแนน | จำนวนเต็ม 1–5 · `CHECK` ที่ DB ด้วย | โจทย์ · 3.5 แปลงเป็น int ไม่ได้ → 400 | — |
| ข้อความรีวิว | ไม่บังคับ · ≤ 1,000 ตัว | ให้ดาวอย่างเดียวได้ | ดีไซน์เขียนว่าต้องมีข้อความ — เลือกผ่อนเพื่อให้รีวิวง่าย |
| ค่าเฉลี่ย | คำนวณสด (ตั้งแต่ Phase 2) | ข้อมูลตรงเสมอ · ปริมาณข้อมูลระดับนี้เร็วพอ | cache ในตารางร้าน: ต้อง sync ทุกครั้งที่มีรีวิว |
| **เรียงตามคะแนน** | `ORDER BY (review_count >= 5) DESC, avg_rating DESC NULLS LAST, review_count DESC` | ตอบคำถามโจทย์ "5.0 จาก 1 รีวิว vs 4.8 จาก 300" — ร้านรีวิวน้อยไปอยู่ท้าย + ป้าย "รีวิวยังน้อย" · อธิบายง่าย ผู้ใช้เข้าใจทันที | **Bayesian average**: แม่นกว่าทางสถิติ แต่ต้องเลือกค่ากลาง/น้ำหนัก และผู้ใช้เห็นอันดับที่ไม่ตรงกับตัวเลขบนการ์ด |
| เกณฑ์ 5 รีวิว | `MinReviewsForRanking = 5` ที่เดียวใน Go · ส่ง `hasEnoughReviews` ให้หน้าเว็บ | เปลี่ยนเกณฑ์ที่จุดเดียว | ให้หน้าเว็บรู้เลข 5 เอง |
| ร้านไม่มีรีวิว | `NULLS LAST` | ไม่มีคะแนน ≠ คะแนนต่ำ แต่ควรอยู่ท้าย | — |
| เรียงตามรีวิว | `review_count DESC, avg_rating DESC` | โจทย์ · ถ้าเท่ากันใช้คะแนนตัดสิน | — |
| sort ผิดค่า | 400 | ไม่เดาเอาเอง | ใช้ค่า default เงียบ ๆ |
| ขีดเส้นท้าย | `ORDER BY ... restaurants.id` | ลำดับคงที่เมื่อค่าเท่ากัน (ไม่สลับไปมาตอน reload) | — |
| รายการรีวิว | ทีละ 20 + ปุ่ม "ดูรีวิวเพิ่ม" (`useInfiniteQuery`) | ร้านที่มี 300 รีวิวไม่ต้องโหลดทั้งหมดทีเดียว | ส่งทั้งหมด |
| `mine` แยกมา | รีวิวของเราอาจไม่อยู่หน้าแรก | ฟอร์มเปิดมาพร้อมค่าเดิมเสมอ | — |
| หลังโพสต์ | invalidate `reviews`, `restaurant`, `restaurants`, `my-bookings` | ตรา/แท่งดาว/ป้าย "รีวิวแล้ว" อัปเดตทันที | — |
| Star picker | ปุ่ม 5 ปุ่ม `aria-pressed` + `aria-label="ให้ N ดาว"` + ป้าย "4 ดาว — ดีมาก" (`aria-live`) | ตามดีไซน์ · ใช้คีย์บอร์ด (Tab/Enter) ได้ · ปุ่มโพสต์ disabled จนเลือกดาว | — |

## ทดสอบแล้ว

- รีวิวซ้ำ 2 ครั้ง → ยังมี 1 แถว ค่าเป็นของครั้งหลัง · เจ้าของรีวิวร้านตัวเอง → 403 · rating 0 / 6 / 3.5 → 400 · ไม่ login → 401
- ข้อมูล: ร้าน A 4.8 (6 รีวิว) · ร้าน B 5.0 (1 รีวิว) → `sort=rating` A มาก่อน B ✓ · ร้านไม่มีรีวิวอยู่ท้ายสุด
- เบราว์เซอร์: เลือก 4 ดาว → "4 ดาว — ดีมาก" · โพสต์แล้วตราคะแนนเปลี่ยนเป็น 4.7 (7 รีวิว) ทันที · มะลิเปิดร้านตัวเองเห็นกล่องล็อก
